# برنامه‌ریز و بهینه‌ساز منوی بوفه رویداد سازمانی

اپلیکیشن وب تک‌صفحه‌ای برای برنامه‌ریزی منوی بوفه رویدادهای سازمانی: تعداد میهمانان، بودجه سرانه و آیتم‌های غذایی را وارد می‌کنید و هزینه، مقدار پخت و ترکیب تغذیه‌ای سفره به‌صورت زنده محاسبه می‌شود.

## اجرا

```bash
npm install
npm run dev      # سرور توسعه
npm run test     # تست‌های واحد (Vitest)
npm run build    # ساخت نسخه‌ی نهایی
```

## ساختار

- `src/lib/calculations.ts` — موتور محاسباتی (تخصیص وزنی بودجه، تعداد پخت، ترکیب تغذیه‌ای سطح سفره) و `calculations.test.ts` برای تست‌های واحد آن.
- `src/lib/recommendations.ts` — منطق تولید توصیه‌های برنامه‌ریز رویداد/آشپز/کارشناس مالی.
- `src/data/defaultSettings.ts` — همه‌ی ثابت‌های قابل‌تغییر (اهداف تغذیه‌ای، وزن رده‌ها، ضریب اطمینان، سقف هزینه) که از صفحه‌ی «تنظیمات رویداد» قابل ویرایش‌اند.
- `data/dishes.json` — دیتابیس غذاها، تولیدشده توسط `scripts/extract_dishes.py` از فایل اکسل سوابق رویدادهای قبلی. جزئیات و تصمیم‌های استخراج در `data/EXTRACTION_NOTES.md` مستند شده‌اند.
- `src/pages/` — پنج بخش اصلی اپ: تنظیمات رویداد، انتخاب غذا، داشبورد جمع‌بندی، توصیه‌های تخصصی، دیتابیس غذاها.

داده‌ی سناریو (بودجه، آیتم‌های انتخابی) و تنظیمات کاربر در `localStorage` مرورگر ذخیره می‌شوند — مگر اینکه یکی از دو حالت زیر را وصل کنید (هر دو اختیاری‌اند و کنار هم هم کار می‌کنند):

- **فایل واقعی روی دیسک** (دکمه‌ی «باز کردن/ایجاد فایل دیتابیس» بالای صفحه، فقط Chrome/Edge) — یک فایل JSON را روی کامپیوترتان انتخاب می‌کنید و از آن پس خودکار در همان فایل ذخیره می‌شود.
- **سلف‌هاست با PHP + MySQL** (زیر XAMPP یا Laragon) — راهنمای کامل زیر.

## سلف‌هاست روی XAMPP یا Laragon (PHP + MySQL)

این حالت اپ را از یک بک‌اند PHP واقعی با دیتابیس MySQL سرو می‌کند — برای اجرا روی دسکتاپ خودتان، تک‌کاربره، بدون نیاز به اینترنت. فرانت هیچ تفاوتی نمی‌کند: به‌محض این‌که ببیند پوشه‌ی `api/` کنارش در دسترس است، خودکار به‌جای `localStorage` از MySQL می‌خواند/می‌نویسد (نوار سبز «متصل به دیتابیس MySQL» بالای صفحه ظاهر می‌شود).

### ۱. ساخت دیتابیس

در phpMyAdmin (یا خط فرمان `mysql`) یک دیتابیس خالی بسازید (مثلاً به نام `buffet_planner`، UTF-8/`utf8mb4`)، سپس کل فایل `db/schema.sql` را روی آن اجرا کنید — همه‌ی جدول‌های لازم را می‌سازد.

### ۲. تنظیم اتصال

فایل `api/config.php` را باز کنید و مشخصات دیتابیستان را وارد کنید (در Laragon/XAMPP پیش‌فرض معمولاً `host=127.0.0.1`، `user=root`، `password` خالی است):

```php
return [
    'driver' => 'mysql',
    'host' => '127.0.0.1',
    'port' => '3306',
    'database' => 'buffet_planner',
    'username' => 'root',
    'password' => '',
    'charset' => 'utf8mb4',
];
```

### ۳. واردسازی اولیه‌ی دیتابیس غذاها

یک‌بار، از همین پوشه‌ی پروژه:

```bash
php api/seed.php
```

دیتابیس غذاهای شرکت کاترینگ (`data/dishes.json`) و تنظیمات/سناریوی پیش‌فرض را در MySQL می‌نویسد. **این اسکریپت را فقط یک‌بار (روی دیتابیس خالی) اجرا کنید** — اجرای دوباره‌اش هر چیزی را که بعداً در برنامه ویرایش کرده باشید بازنویسی می‌کند.

### ۴. ساخت فرانت و قرار دادن کنار api/

```bash
npm run build
```

خروجی پوشه‌ی `dist/` را همراه با کل پوشه‌ی `api/` (و `api/config.php` ویرایش‌شده) داخل ریشه‌ی وب سرورتان کپی کنید — مثلاً در Laragon: `C:\laragon\www\buffet-planner\`، در XAMPP: `C:\xampp\htdocs\buffet-planner\`. ساختار نهایی باید این‌طور باشد:

```
buffet-planner/
├── index.html          ← از dist/
├── assets/             ← از dist/
├── favicon.svg          ← از dist/
└── api/                ← کل پوشه‌ی api/ (config.php را قبلاً ویرایش کرده‌اید)
```

### ۵. باز کردن

با Apache روشن (از پنل Laragon/XAMPP)، به آدرس `http://localhost/buffet-planner/` بروید — نوار سبز «متصل به دیتابیس MySQL» یعنی اتصال برقرار است. از این به بعد هر تغییری در برنامه با کمی تأخیر خودکار در MySQL ذخیره می‌شود؛ برای دیدن دیتای خام می‌توانید از phpMyAdmin روی جدول‌های `dishes`، `dish_ingredients`، `ingredient_price_log`، `custom_ingredients`، `plan`، `settings` نگاه کنید.

نیازی به Node.js روی سرور نیست — فقط برای مرحله‌ی `npm run build` (یک‌بار، روی کامپیوتر توسعه) لازم است؛ خروجی نهایی فقط HTML/CSS/JS استاتیک + چند فایل PHP است.
